# Функционал назначения мастера на бронирование

## Что добавлено

### 1. Backend API (server/routes/owner.routes.ts)

Добавлен новый эндпоинт для владельцев салонов:

**PATCH `/api/owner/bookings/:id/assign-master`**

Позволяет владельцу назначить или изменить мастера для бронирования.

#### Параметры:

- `id` (path) - ID бронирования
- `masterId` (body) - ID мастера или `null` для отмены назначения

#### Валидация:

- ✅ Проверяет, что бронирование существует
- ✅ Проверяет, что владелец является владельцем салона
- ✅ Проверяет, что мастер принадлежит этому салону
- ✅ Разрешает установить `null` для отмены назначения

#### Пример запроса:

```json
{
  "masterId": "793adc45-de52-47bc-8118-8446064a3a6e"
}
```

### 2. Frontend UI (client/src/pages/owner-salon.tsx)

В списке бронирований добавлен выпадающий список (Select) для назначения мастера.

#### Возможности:

- 📋 Показывает текущего назначенного мастера
- 🔄 Позволяет переназначить мастера
- ❌ Позволяет отменить назначение ("Нет мастера")
- 🔔 Показывает уведомление после успешного назначения

#### UI компоненты:

```tsx
<Select
  value={booking.masterId || "unassigned"}
  onValueChange={(value) => {
    const masterId = value === "unassigned" ? null : value;
    assignMasterMutation.mutate({ bookingId: booking.id, masterId });
  }}
>
  <SelectTrigger className="w-[180px]">
    <SelectValue placeholder="Выберите мастера" />
  </SelectTrigger>
  <SelectContent>
    <SelectItem value="unassigned">Нет мастера</SelectItem>
    {masters?.map((master) => (
      <SelectItem key={master.id} value={master.id}>
        {master.name}
      </SelectItem>
    ))}
  </SelectContent>
</Select>
```

## Как это работает

### Сценарий 1: Клиент создаёт бронирование без выбора мастера

1. Клиент выбирает салон и услугу
2. НЕ выбирает конкретного мастера (или выбирает "Любой")
3. Бронирование создаётся с `masterId: null`
4. Владелец салона видит это бронирование
5. Владелец назначает мастера через выпадающий список
6. Мастер теперь видит это бронирование в своём кабинете

### Сценарий 2: Клиент создаёт бронирование с выбором мастера

1. Клиент выбирает салон, услугу и конкретного мастера
2. Бронирование создаётся с `masterId: "xxx"`
3. И владелец, и мастер сразу видят это бронирование
4. Владелец может переназначить на другого мастера при необходимости

### Сценарий 3: Отмена назначения мастера

1. Владелец открывает список бронирований
2. Выбирает "Нет мастера" в выпадающем списке
3. `masterId` становится `null`
4. Бронирование больше не видно мастеру, только владельцу

## Почему мастер не видел бронирование?

### Проблема:

Эндпоинт `/api/master/bookings` фильтрует только по `eq(bookings.masterId, result.master.id)`.

Когда клиент создаёт бронирование без выбора мастера, `masterId = null`, поэтому условие не выполняется и мастер не видит бронирование.

### Решение:

Владелец салона теперь может назначить мастера на бронирование, и после этого мастер увидит его в своём кабинете.
