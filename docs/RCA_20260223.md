# RCA — Root Cause Analysis
**Дата**: 2026-02-23
**Инцидент**: ErrorBoundary на всех кабинетах в проде

---

## Симптомы

- Все страницы (`/client`, `/owner`, `/admin`) показывают "Что-то пошло не так" (ErrorBoundary)
- В консоли браузера:
  - `Minified React error #321`
  - `NotFoundError: Failed to execute 'removeChild' on 'Node'`
  - CSP blocked: `googletagmanager.com`, `fonts.googleapis.com`
  - i18n ключи отображаются как текст: `marketplace.client.title`, `marketplace.client.tabs.bookings`
  - `Sentry DSN not configured`

---

## Причины (по приоритету)

### Причина №1 — CSP блокировал GTM (КРИТИЧНО)

**Симптом**: `Refused to load script 'https://www.googletagmanager.com/gtm.js'`

**Почему**: в `server/index.ts` CSP не включал `googletagmanager.com` в `script-src`.
GTM вставлял `<script>` через `f.parentNode.insertBefore(j, f)`, CSP блокировал загрузку,
скрипт падал на полпути → DOM оставался в несогласованном состоянии.

**Цепочка**: CSP блокирует GTM → GTM ломает DOM → React пытается удалить ноду,
которую GTM уже переместил → `removeChild` на чужой ноде → React Error #321 →
ErrorBoundary на всех страницах, которые используют layout с GTM.

**Фикс**: добавлены `googletagmanager.com`, `google-analytics.com`, `fonts.googleapis.com`,
`fonts.gstatic.com`, `*.sentry.io` в CSP директивы.

---

### Причина №2 — отсутствующие i18n ключи (ВЫСОКИЙ)

**Симптом**: `marketplace.client.title` вместо "Личный кабинет"

**Почему**: в коде используется `t("marketplace.client.title")` и ~178 других ключей
в неймспейсе `marketplace.client.*`, но этот блок **полностью отсутствовал** во всех
трёх файлах переводов (`en.json`, `ru.json`, `uz.json`).

i18next возвращал ключ как fallback вместо перевода.

**Фикс**: добавлен полный блок `marketplace.client` (83 ключа) во все 3 файла локалей.

---

### Причина №3 — Sentry не настроен (СРЕДНИЙ)

**Симптом**: `Sentry DSN not configured. Error monitoring disabled.`

**Почему**: в `.env` отсутствовали `VITE_SENTRY_DSN` и `SENTRY_DSN`.
Без Sentry инцидент диагностировался "по скринам" вместо нормального стектрейса.

**Фикс**: добавлены placeholder'ы в `.env`. На проде нужно прописать реальный DSN.

---

### Причина №4 — DOM mutation в booking-management (НИЗКИЙ)

**Симптом**: `document.body.appendChild(a)` / `document.body.removeChild(a)` для CSV экспорта

**Почему**: стандартный паттерн "создать `<a>` → append → click → remove" работает,
но добавляет элемент в React-управляемый DOM (`<body>`), что потенциально конфликтует
если React ре-рендерит `<body>` в момент cleanup.

**Фикс**: убран `appendChild`/`removeChild` — скачивание теперь через `a.click()` без вставки в DOM.

## Что пошло не так в процессе

1. **Нет staging-среды с теми же CSP что в проде** → ошибка не поймана до прода
2. **Нет Sentry** → диагностика слепая
3. **Нет smoke-тестов** → "ErrorBoundary на странице" не детектируется автоматически
4. **i18n ключи не валидировались** → можно было поймать скриптом до деплоя

## Как не допустить повторения

### Техническое

- [x] CSP включает все внешние домены (GTM, Fonts, Sentry)
- [x] i18n ключи добавлены в локали
- [x] DOM cleanup не вставляет в React-управляемый DOM
- [ ] Sentry DSN прописать на проде
- [ ] Playwright smoke: проверка что ErrorBoundary не показывается
- [ ] Скрипт валидации i18n ключей запускать в CI

- [ ] Staging с identical CSP к prod
- [ ] Чеклист перед деплоем (см. `docs/DEPLOY_CHECKLIST.md`)
